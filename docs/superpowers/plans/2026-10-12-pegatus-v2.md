# Pegatus V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build a portable ECC-based workflow kit retaining every approved core capability while focusing on .NET 10 and React 19.

**Architecture:** Shared Markdown catalogs and a Node.js ESM CLI own workflow policy and portable state. Adapters generate host-specific artifacts and report enforcement limits. Upstream components are pinned, audited, and selectively adapted with provenance.

**Tech Stack:** Node.js >=22, JavaScript ESM, node:test, JSON, Markdown; Windows and Linux. Use built-in libraries for core operations; pin AgentShield as a security dependency after compatibility validation.

**Spec:** ../specs/2026-10-12-pegatus-v2-design.md

## Approved browser-testing extension

The [extension plan](2026-10-21-browser-tester.md) records implementation and actual checks. Host-level Playwright MCP is a separate prerequisite, not an application dependency or an automatically provisioned installer feature. Native browser/delegation qualification remains open; see [browser testing](../../browser-testing.md).

## Global Constraints

- Claude Code, Codex, and Antigravity are the first-release hosts; Windows and Linux are required.
- Follow solution instructions before requirements refinement, design, implementation, review, verification, and resume.
- Preserve agents, skills, commands, hooks, rules, memory, continuous learning, verification, token optimization, orchestration, and AgentShield/security.
- Support project/workspace and user-wide installation; project configuration overrides defaults.
- Preserve existing instruction generators and user-edited files.
- Vaults own project knowledge where configured by solution instructions; `.pegatus/` owns workflow state.
- Durable learning promotion requires human approval; host/user instruction authority is unchanged.
- Default concurrency: two workers. Default verification repair limit: three rounds.
- Do not publish, deploy, push, or modify production databases as part of this plan.
- No claim of equal host enforcement or security scanner completeness without measured evidence.

## Review Focus

1. Windows paths, spaces, symlinks/junctions, and Linux case sensitivity must not cause writes outside installation roots (Tasks 2 and 7).
2. Multiple sessions and interrupted writes must not corrupt progress or grant stale approvals (Task 3).
3. Stale indexes, nested instructions, and a missing vault tool must not trigger silent rescanning or assumption-driven design (Task 4).
4. Malformed scanner output and unsupported host features must never appear as successful protection (Tasks 8 and 10).
5. Edited files, duplicate installation scopes, and instruction generators must survive update and uninstall (Task 7).

## Delivery structure and dependencies

This is one integrated first-release plan with independently testable units, not separate product expansions. Tasks 1–4 establish the contracts; Task 5 consumes them; Tasks 6–9 add required execution capabilities; Task 10 qualifies the complete kit. The first release is incomplete until all categories pass acceptance. Parallel implementation is possible only after interfaces are established and the user selects an execution method.

```text

src/config.mjs                 defaults, override resolution, validation
src/paths.mjs                  canonical roots and containment
```

Shared records: `Result={status:'passed'|'failed'|'blocked'|'skipped', evidence:[], reasons:[]}`; `Evidence={command,args,cwd,exitCode,startedAt,finishedAt,codeState,outputPath}`; `Context={instructionPaths,knowledgeRefs,discoveryCommands,uncertainties}`. All state records have `schemaVersion:1`. Functions accept injected execution and filesystem dependencies where failure simulation is needed.

Commit after each passing task when a Git repository exists. The current workspace is not a Git repository; at execution initialize it or use the user's selected repository setup before committing. Plan creation itself does not initialize Git.
