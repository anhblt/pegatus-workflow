# Configuration security

Run `npm ci --ignore-scripts --no-audit --no-fund` against the committed root lock before using the scanner. This installs the local `ecc-agentshield@1.6.0` executable and exactly the 61 dependency nodes from the audited lock. Pegatus never runs an unpinned `npx`, installs globally, or downloads dependencies during scanning. Node >=22 is the Pegatus runtime requirement. Offline distribution must supply the locked dependency tree or a prepared npm cache; copying the JavaScript files alone is insufficient.

Use `node bin/pegatus.mjs security --root <explicit-existing-root> --file <relative-config>`, repeating `--file` for each relevant instruction, agent, skill, hook, permission or MCP file. It does not recursively scan the user's source tree. Exit codes are 0 passed, 1 scanner failure, 2 invalid CLI usage, and 3 blocked findings/coverage. Completion coordinators must call the same `scanAgentConfig` function on affected configuration and require `status === 'passed'`; application changed-code review remains a separate responsibility in `catalog/agents/security-reviewer.md`.

The scanner command is the current Node executable followed by the resolved local `ecc-agentshield/dist/index.js`, `scan --path <temporary-isolated-root> --format json`. Only declared files enter that temporary root. No shell is used. `--fix`, `--deep`, `--opus`, `--injection`, `--sandbox`, `--supply-chain-online`, runtime and watch modes are absent; no provider key is supplied. The default scans source statically, without executing hooks or transmitting source. Timeout defaults to 30 seconds, bounded output to 2 MiB. Scanner errors, truncation, malformed JSON/TOML, missing binaries, nonstandard exits, and malformed findings fail scanning. Exit 2 is accepted as a completed scanner run only when the parsed summary records critical findings; the security gate remains blocked until disposition.

Measured discovery requires the reported file count to equal the expected count in the isolated root. A zero-file result cannot pass for any requested AgentShield file. A discovery mismatch leaves all those candidates uncovered because the report does not identify an inventory of scanned files. Unexpected finding locations fail scanning. Unknown input formats remain explicitly uncovered and block the gate.

## Coverage and limits

The wrapper's AgentShield allowlist retains actual published scanner paths: root `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md`, `AGENTS.override.md`, `GEMINI.md`; `.claude/CLAUDE.md`, `.codex/AGENTS.md`, `.gemini/GEMINI.md`; root and `.claude/` settings/MCP JSON; `.claude.json`; root or `.codex/config.toml`; `.codex/hooks.json`; `.gemini/settings.json`; `mcp_config.json`; direct Markdown files under root or `.claude/` agents/subagents/rules/commands/contexts; direct `.codex/agents/*.toml`; and direct supported JSON/JS/CJS/MJS/SH/BASH/ZSH/Python files under root or `.claude/` hooks. Individual paths still require measured discovery, not an allowlist assumption. Nested skill files are not discovered by its shallow skill traversal.

Known Markdown files under `.agents/skills`, `.agents/workflows`, `.agents/rules`, `.gemini/config/global_workflows`, `.claude/skills` and `.pegatus/runtime` receive separately labeled `pegatus-static@1` checks. `.gemini/antigravity/mcp_config.json` also receives these checks after JSON parsing. They look for embedded credential assignments, the literal instruction override phrase, command interpolation from user/input/prompt variables, and unsafe permission tokens. These checks are deliberately limited content heuristics. They do not establish host semantic equivalence, full MCP validation, complete secret detection, hook safety, or application-code security. `coverage.agentShield`, `coverage.pegatusStatic`, `coverage.uncovered`, `coverage.filesScanned` and `coverage.limits` identify the distinction. Zero AgentShield files with nonempty completed Pegatus checks means supplemental static coverage, never a clean AgentShield scan.

Install/update administration scans **desired staged bytes**, including unchanged desired configurations, before managed mutations. Its scope includes generated native configuration and every Markdown instruction/reference in the portable runtime catalog and upstream skill trees. Runtime application modules, package metadata, notices and other nonconfiguration assets are excluded; this gate does not attest that the entire kit's code is secure. Unknown desired files inside host configuration directories remain uncovered. Existing unrelated user configuration is preserved; scan it explicitly when relevant. Ownership conflicts and compare-and-swap protection still precede mutation. Removal-only uninstall uses the installer's explicit root, unchanged-file ownership and compare-and-swap checks, and reports `coverage.operation: 'removal-only'`; removed files are not falsely presented as scanned.

Windows/Node 24 actual fixtures discovered two files in a native Codex-role/Claude-settings scan, exited 0 with no critical findings, and blocked an injected CLAUDE instruction with observed critical findings. Published discovery includes Codex TOML roles/configuration and generic harness JSON; this corrects the earlier broad Claude-only characterization. Discovery is not complete native host semantics. Linux execution and practical Claude/Codex/Antigravity acceptance remain Task 10 qualification gates. AgentShield also produces critical findings for plain Markdown missing instruction-boundary or secret-disclosure safeguards. The generated wrappers now state trusted-instruction, external-content, secret-disclosure, authorized-scope and role-privilege boundaries; a real Claude installation passes the critical gate. A negated phrase about overriding system instructions initially produced a scanner false positive, so equivalent unambiguous wording now prohibits modifying trusted instructions. No finding is automatically suppressed.

## Reviewed exceptions and evidence

Critical findings block until a trusted caller supplies an explicit human disposition. CLI `--exceptions <review.json>` reads a root-contained `{schemaVersion:1, exceptions:[...]}` record. Every accepted record requires `fingerprint`, `disposition:'accepted-risk'`, `reviewedBy`, `reviewedAt` and a nonempty `reason`. The API takes the same array via `exceptions`. These are caller trust inputs; scanner output and learning content cannot provide dispositions. Install integration callers can pass `securityPreflight: plan => scanInstallPlan(plan,{exceptions})`. No automatic suppression or remediation occurs.

Fingerprints cover the raw finding identity/severity/location/message/evidence and the SHA-256 of its file bytes. Any changed finding or file invalidates an old exception. Configuration changes during scanning invalidate the result. Returned findings keep suppression provenance and remediation when supplied by the scanner. Raw JSON/stdout/stderr are never persisted or returned. Evidence contains the executable, fixed args, isolated cwd, times, exit and scanned-content fingerprint; `codeState` also binds supplemental checks to the scanned bytes. Error strings and findings are bounded and redact credential assignments, bearer tokens, private keys, known provider token shapes and caller-supplied literal `redactions`. Heuristics cannot guarantee every secret is recognized: do not publish raw inputs or scanner output.

## Deprecated glob dependency

`npm ci` warns that locked `glob@11.1.0` is deprecated. The maintained project advisory [GHSA-5j98-mcp5-4vw2 / CVE-2025-64756](https://github.com/isaacs/node-glob/security/advisories/GHSA-5j98-mcp5-4vw2) identifies 11.1.0 as patched and describes an affected `glob -c/--cmd` CLI path. Pegatus invokes the AgentShield Node CLI directly with `shell:false`, never the glob CLI. Inspection of the installed AgentShield bundle found no glob import/call on this integration path. The [deprecation clarification issue](https://github.com/isaacs/node-glob/issues/644) discusses the warning applying to the patched releases too. This is a maintenance warning requiring future upstream dependency review, not evidence that this particular fixed CVE affects the wrapper. No unrelated dependency upgrade was performed and no comprehensive vulnerability-clear claim is made. The lock also preserves the `node-domexception@1.0.0` deprecation warning.
