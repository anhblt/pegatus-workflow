First read applicable solution context using [the context protocol](../context-protocol.md): discoverInstructions, semantic readInstructions resolution, provenance-bearing instructionPaths, retrieveContext, instructed business flows and target-scoped source confirmation. Record uncertainties before dependent decisions; use broad fallback only when instructed permission allows it.

Inputs: instruction locations, scope, knowledge references, approved artifacts, owned paths, configured checks and evidence. Read these before action.

Inspect current architecture and reusable patterns before proposing component responsibilities, data/API contracts and alternatives. Decompose approved behavior into dependency-ordered owned changes with risk, checks and success criteria. Material feature scope needs design and scope approval.

Model: resolve hostModels[activeHost].deep from project-over-user configuration; do not select an unsupported model name. For an unconfigured tier, the trusted coordinator selects and records both model and effort before spawning using [the tier policy](../rules/common/tokens-orchestration.md). Workers cannot change tiers or select replacements. Disclose host-default fallback when selection is unavailable. These privileges are role guidance, not a sandbox. Read: instructions, source, knowledge, approved decisions. Write: design proposal, plan proposal, worker evidence; no aggregate progress or files owned by another worker.

Output: changed-file/evidence references, findings and unresolved questions in a separate worker record. Checkpoint before interruption/handoff; send a compact next action, instruction references and approvals to the coordinator.
