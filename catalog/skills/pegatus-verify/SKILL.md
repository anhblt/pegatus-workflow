name: pegatus-verify
description: Direct verify procedure for Pegatus tasks; invoke when verify is requested or routed by the main workflow.
---

First read applicable solution context using [the context protocol](../../context-protocol.md): discoverInstructions, semantic readInstructions resolution, provenance-bearing instructionPaths, retrieveContext, instructed business flows and target-scoped source confirmation. Record uncertainties before dependent decisions; use broad fallback only when instructed permission allows it.

Inputs: task brief or saved task ID, classification/scope, discovered instruction locations, knowledge references, relevant approved artifacts and project-selected checks.

Follow the [shared execution guide](../pegatus-execute/execution-guide.md) for independent substantial-work testing and final-state evidence. Confirm relevant source writers stopped and record actual identity/context relationship and tracked/untracked working-content observations before/after checks. A delegated verifier returns evidence/findings without source repairs or recursively dispatching review/execution; the coordinator owns next steps. A direct testing request keeps its scope. Explicit inline choice or unavailable/disallowed delegation requires accurate disclosure of absent independence.

For failed checks needing diagnosis or repair, follow the [shared debugging guide](../pegatus-investigate/debugging-guide.md). Require causal evidence and a focused hypothesis before authorized repairs; preserve non-mutating diagnosis callbacks, configured repair budgets, unchanged-failure stops and actual result distinctions. Missing prerequisites are evidence gaps, not reasons for speculative code changes. Re-run relevant checks on the final state before claiming a fix.

Select browser checks when the task changes observable interactions, navigation, forms, rendered states, layout or responsive behavior, and always when explicitly requested. Internal/type-only, tooling or documentation tasks without UI impact can omit them with a recorded reason. Delegate selected checks through [pegatus-browser-test](../pegatus-browser-test/SKILL.md), supplying target URL/startup context, acceptance scenarios and evidence ownership. The general verifier coordinates frontend checks; browser-tester exercises the browser. If delegation is unavailable follow that procedure inline and disclose the limitation. Selected browser checks require current browser evidence; build/type/lint success cannot substitute. Missing Playwright, application access or login leaves the affected check BLOCKED, not silently skipped. Keep browser reports separate from executable-command evidence and preserve completion gates.

Use project-selected command/args/cwd/requires/shell specifications; never substitute hardcoded Bash pipelines or a universal coverage target. Run required build/type/lint/tests and applicable configuration security scans with exact exit codes and prerequisites. Return evidence for the coordinator's separate changed-code review. Preserve evidence tied to final repository state; edits invalidate affected evidence. Runtime repair callbacks retain their diagnosis/authorization/repair/review/recheck order and consume the same task repair budget across phases/resume; default repairLimit three. Their repair review does not automatically satisfy the outer fresh review. A missing prerequisite is BLOCKED or NOT RUN, including unavailable Docker integration tests; never a clean pass.

Required checks: verify the operation's output against task acceptance and relevant configured checks; preserve failures, missing prerequisites and unresolved context as evidence. Reconfirm source when documentation is stale. Use the implemented runtime APIs for installation, hooks, reviewed learning and configuration scanning where applicable. Distinguish host guidance and generated entry points from actual native execution or enforcement; report unavailable tools and continue only independent safe actions.

Output records: .pegatus/work/<task-id>/brief.md, progress.json, evidence/ and report.md as applicable; spec.md/plan.md only when required by feature classification; lessons/ holds proposals. Use atomic state APIs and coordinator-only aggregate writes. Checkpoint after meaningful work and before handoff/compaction/interruption with approvals, next action and uncertainties.
